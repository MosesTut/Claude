## iOS Screenshots

### Required Sizes

**iPhone 6.7" Display** (Mandatory - one of these):
- iPhone 15 Pro Max: 1290 × 2796 pixels
- iPhone 14 Pro Max: 1290 × 2796 pixels
- Portrait orientation only

**iPhone 6.5" Display** (Alternative to 6.7"):
- iPhone 11 Pro Max: 1242 × 2688 pixels
- iPhone XS Max: 1242 × 2688 pixels
- Portrait orientation only

**iPad Pro 12.9" (6th gen)** (Optional but recommended):
- Size: 2048 × 2732 pixels (portrait) or 2732 × 2048 pixels (landscape)
- Minimum: 2 screenshots
- Recommended: 3-5 screenshots

**Note**: You MUST provide either 6.7" OR 6.5" screenshots. Apple will not accept submission without at least one of these sizes.

**Minimum Required**: 3 screenshots
**Recommended**: 5 screenshots

#### Screenshot 1: AI Disclosure ⚠️ **CRITICAL FOR APPLE APPROVAL**

**Screen**: `AIDisclosureScreen`

**What to Show**:
- Title: "AI Transparency"
- Warning icon: ⚠️
- Disclosure message: "Timbuktoo uses artificial intelligence to generate travel recommendations..."
- **CRITICAL**: Mandatory consent checkbox visible: "I understand itineraries are AI-generated"
- "Agree & Continue" button (disabled state to show checkbox is required)

**Caption** (optional, appears below screenshot in App Store):
"Transparent AI-powered recommendations"

**Why This Screenshot is Critical**:
- Apple requires prominent AI disclosure in screenshots
- Must show that user consent is mandatory
- Demonstrates compliance with App Store Review Guidelines 5.1.1(vi)

**Production Notes**:
- Take screenshot BEFORE checking the checkbox (to show unchecked state)
- Ensure warning box (yellow background) is clearly visible
- Use high-contrast, readable text

## Screenshot Production Guide

### Method 1: Real Device Screenshots (Recommended)

**iOS**:
1. Build app on physical iPhone (6.7" or 6.5" display)
2. Navigate to desired screen
3. Take screenshot: Press `Side Button + Volume Up` simultaneously
4. Screenshots saved to Photos app
5. AirDrop to Mac or use Image Capture to transfer
6. Crop if needed (but avoid cropping status bar for consistency)

**Android**:
1. Build app on physical Android device (1080×1920 resolution)
2. Navigate to desired screen
3. Take screenshot: Press `Power + Volume Down` simultaneously
4. Screenshots saved to Gallery app
5. Transfer via USB or cloud (Google Photos, Dropbox)
6. Resize if needed (use Photoshop or online tool)

**Advantages**:
- ✅ Most realistic (real fonts, colors, layout)
- ✅ Shows actual app performance
- ✅ Easier to produce (no manual mockups)

**Disadvantages**:
- ❌ Requires physical device
- ❌ May have test data or debug info (clean up first)

---

### Method 2: Simulator/Emulator Screenshots

**iOS Simulator** (Xcode):
1. Open Xcode → `Window` → `Devices and Simulators`
2. Select iPhone 15 Pro Max (6.7" display)
3. Run app on simulator: `expo start` → `i` for iOS
4. Navigate to desired screen
5. Take screenshot: `Cmd + S` in Simulator window
6. Screenshots saved to Desktop
7. Rename and organize

**Android Emulator** (Android Studio):
1. Open Android Studio → `AVD Manager`
2. Create virtual device: Pixel 5 (1080×1920)
3. Run app on emulator: `expo start` → `a` for Android
4. Navigate to desired screen
5. Take screenshot: Camera icon in emulator toolbar
6. Screenshots saved to Desktop

**Advantages**:
- ✅ No physical device needed
- ✅ Perfect resolution control
- ✅ Easy to retake/iterate

**Disadvantages**:
- ❌ May have "Simulator" badge (remove in post-production)
- ❌ Slightly different rendering than real device

---

### Method 3: Design Tool Mockups (Advanced)

**Tools**: Figma, Sketch, Adobe XD

**Process**:
1. Export app UI designs from Figma/Sketch
2. Place in device frame template (iPhone 15 Pro Max, Pixel 5)
3. Add realistic data (venues, cities, itineraries)
4. Export as PNG (1290×2796 for iOS, 1080×1920 for Android)

**Advantages**:
- ✅ Full control over UI/data
- ✅ Pixel-perfect screenshots
- ✅ Easy to create variations for A/B testing

**Disadvantages**:
- ❌ Time-consuming (requires design skills)
- ❌ May not match final app perfectly (if UI changes)

---

### Method 4: Screenshot Tools (Recommended for Polish)

**Tools**:
- **Fastlane Frameit**: Add device frames around screenshots
- **AppLaunchpad**: Create marketing screenshots with text overlays
- **Screenshot Studio**: Automate screenshot generation

**Fastlane Frameit Example**:
```bash
# Install Fastlane
gem install fastlane

# Add device frames to screenshots
fastlane frameit

# Generates screenshots with iPhone frame around them
```

**Use Case**: Convert plain screenshots (Method 1 or 2) into polished marketing screenshots with device frames.

## Screenshot Content Guidelines

### What to Include

✅ **Real, Production UI**:
- Use final app design (not wireframes or mockups)
- Match actual app colors, fonts, spacing
- Show polished UI (no broken layouts or missing images)

✅ **Realistic Data**:
- Use real city names (Bangkok, Lisbon, Tokyo)
- Use realistic venue names ("Thip Samai Pad Thai", not "Restaurant 1")
- Use realistic AI-generated reasoning (2-3 sentences, specific to user preferences)
- Use realistic weather ("Sunny, 32°C", not "Weather")

✅ **AI Disclosure Visible**:
- Screenshot 1 (iOS) and Screenshot 1 or 4 (Google Play) MUST show AI disclosure
- Banner or consent checkbox must be clearly readable

✅ **User Consent Visible** (iOS especially):
- Show unchecked checkbox to demonstrate it's required
- Show warning box or alert (yellow background)

---

### What to Avoid

❌ **Test Data**:
- "Lorem Ipsum" placeholder text
- "Test User", "user@example.com"
- "Restaurant 1", "Activity 2"
- "City Name", "Country Name"

❌ **Debug Info**:
- Redux DevTools overlay
- Console logs visible on screen
- "Development Build" banner
- API endpoints or tokens visible

❌ **Broken UI**:
- Missing images (broken image icons)
- Text overflow or truncation errors
- Overlapping UI elements
- Wrong colors or fonts

❌ **Inappropriate Content**:
- Offensive language
- Sexual content
- Violence or gore
- Illegal activities

❌ **Misleading Content**:
- Features not in the app (e.g., booking, payments in MVP)
- "100% accurate AI" claims
- Fake reviews or testimonials

## Quality Checklist

Before uploading screenshots to App Store Connect or Google Play Console:

### Technical Quality
- [ ] Correct dimensions (1290×2796 for iOS 6.7", 1080×1920 for Google Play)
- [ ] PNG or JPG format (PNG recommended for text clarity)
- [ ] RGB color space (no CMYK)
- [ ] No transparency (use solid backgrounds)
- [ ] Portrait orientation (unless iPad landscape)
- [ ] File size under limits (8 MB for Google Play, 20 MB for iOS)

### Content Quality
- [ ] AI disclosure visible in at least one screenshot (both iOS and Google Play)
- [ ] User consent checkbox visible (iOS Screenshot 1)
- [ ] Realistic data (real city names, venue names, descriptions)
- [ ] No placeholder text ("Lorem Ipsum", "Test User")
- [ ] No debug info (Redux, console logs)
- [ ] UI matches final app design
- [ ] Text is readable (not too small, good contrast)

### Compliance
- [ ] No inappropriate content (offensive, sexual, violent)
- [ ] No misleading features (show only what's in the app)
- [ ] No fake reviews or testimonials
- [ ] Privacy Policy and Terms links visible (Settings screenshot if included)
- [ ] Data deletion option visible (Settings screenshot if included)

### Branding
- [ ] Consistent color scheme across all screenshots
- [ ] App logo/branding visible where appropriate
- [ ] Professional design (clean, modern, not cluttered)
- [ ] Matches app icon and feature graphic style

## Screenshot Production Timeline

**Timeline**: 1-2 days for complete screenshot set

**Breakdown**:
- Setup (devices, simulators, test data): 2 hours
- Screenshot capture (5-6 screenshots): 1 hour
- Image editing (crop, resize, export): 1 hour
- Quality review and iteration: 1-2 hours
- Upload to App Store Connect / Play Console: 30 minutes

**Total**: 5-6 hours (can be done in 1-2 days with breaks)

## Post-Production Checklist

After creating all screenshots:

- [ ] Review on multiple screen sizes (desktop, mobile web preview)
- [ ] Get feedback from team (product, marketing, legal)
- [ ] Verify AI disclosure is prominent and readable
- [ ] Ensure all text is spelled correctly (no typos)
- [ ] Check file naming convention is consistent
- [ ] Create backup copies (save in Google Drive / Dropbox)
- [ ] Upload to App Store Connect / Play Console
- [ ] Preview in store listing (use App Store Connect preview feature)

## Common Mistakes to Avoid

❌ **Wrong Dimensions**:
- Using 1080×1920 for iOS (should be 1290×2796 for 6.7")
- Using landscape when portrait is required

❌ **Missing AI Disclosure**:
- No AI disclosure visible in any screenshot
- AI disclosure text too small to read

❌ **Low Quality**:
- Blurry or pixelated images
- Low-contrast text (hard to read)
- Poor color choices (neon colors, clashing)

❌ **Inconsistent UI**:
- Screenshots from different app versions
- Inconsistent branding (different logos, colors)

❌ **Feature Parity**:
- Showing features not in the app (e.g., booking in MVP)
- Showing iOS features in Google Play screenshots (and vice versa)
