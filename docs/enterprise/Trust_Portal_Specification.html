Security

Timbuktoo implements industry-leading security practices to protect customer data at every layer.

Data Protection

  • Encryption at Rest: All data encrypted using AES-256 (AWS RDS, S3)
  • Encryption in Transit: TLS 1.2+ for all API communication
  • Key Management: AWS KMS with automatic key rotation
  • Database Security: PostgreSQL with row-level security and SSL connections

Access Control

  • Role-Based Access Control (RBAC): Least privilege principle enforced
  • Multi-Factor Authentication (MFA): Required for all production access
  • Access Reviews: Quarterly reviews of user permissions
  • Session Management: 30-day JWT expiration, secure token storage

Infrastructure Security

  • Tenant Isolation: Logical separation of customer data
  • Environment Separation: Dev, staging, and production environments isolated
  • Network Security: VPC with private subnets, security groups, and NACLs
  • Continuous Monitoring: Real-time alerts for suspicious activity (Datadog, AWS CloudWatch)

Vulnerability Management

  • Dependency Scanning: Automated scanning for vulnerable dependencies (Dependabot)
  • Penetration Testing: Annual third-party penetration tests
  • Patch Management: Critical patches applied within 7 days
  • Security Audits: Quarterly internal security audits

Privacy

Timbuktoo is committed to protecting user privacy and providing transparency about data practices.

Data Collection

  • Email Address: Account creation and authentication
  • Travel Preferences: Personalization (interests, food, budget, dates)
  • AI-Generated Itineraries: Stored for user access
  • Usage Data: Aggregated analytics (crash reports, session duration)

Data NOT Collected

  • ❌ Location data (GPS, precise location)
  • ❌ Contacts, photos, camera, microphone
  • ❌ Payment information (Stripe/Apple/Google handles)
  • ❌ Device IDs or advertising identifiers (IDFA/AAID)
  • ❌ Browsing history or search history

Data Usage

  • Personalization: Travel preferences used only to generate itineraries
  • Analytics: Aggregated usage data (no PII) for app improvement
  • No Selling: User data is NEVER sold or shared with third parties
  • Service Providers: AWS (infrastructure), Anthropic (AI API), Stripe (payments) are service providers, not third parties

Data Retention & Deletion

  • Account Data: Retained until user requests deletion
  • Itineraries: Retained for 2 years after last login (auto-deleted)
  • Usage Logs: Retained for 90 days (auto-deleted)
  • Deletion SLA: 30 days from user request (GDPR/CCPA compliant)
  • How to Delete: Settings → Delete My Data (in-app) or email support@timbuktoo.app

AI Governance

Timbuktoo uses artificial intelligence responsibly and transparently, with governance controls to ensure quality and safety.

AI Transparency

  • User Disclosure: AI usage disclosed during onboarding (mandatory consent checkbox)
  • In-App Disclosure: Every AI-generated itinerary displays banner: "⚠️ This itinerary was generated by AI"
  • Informational Only: All AI recommendations are informational and should be independently verified
  • No Guarantees: Timbuktoo does not guarantee accuracy, availability, pricing, or safety of AI recommendations

Human Feedback Loops

  • User Feedback: Users can rate itineraries as "Helpful" or "Not Helpful"
  • Report Mechanism: Users can report issues (inaccurate, inappropriate, missing information, other)
  • Compliance Review: All reports reviewed by compliance team within 48 hours
  • Continuous Improvement: Feedback used to improve AI prompts and agent orchestration

Deterministic Orchestration

  • Multi-Agent Workflow: 3 sequential agents (City Selection, Local Expert, Concierge)
  • Prompt Versioning: All prompts version-controlled (Git) with changelog
  • Workflow Versioning: Agent orchestration logic version-controlled
  • Rollback Capability: Can roll back to previous prompt/workflow versions if quality degrades

AI Model & Provider

  • Model: Anthropic Claude 3.5 Sonnet
  • Provider: Anthropic (SOC 2 Type II certified)
  • Data Processing: Anthropic does NOT store user data for model training
  • Model Updates: Tested in staging before production deployment

Content Moderation

  • Input Filtering: User preferences validated (no offensive content)
  • Output Filtering: AI-generated content scanned for inappropriate language
  • Human Review: Flagged content reviewed by compliance team
  • Response Time: Inappropriate content reports reviewed within 1 hour (business hours)

Availability

Timbuktoo maintains high availability with real-time monitoring and incident response.

Uptime Commitment

  • Target: 99.9% uptime (< 43 minutes downtime per month)
  • Measurement: Monthly uptime percentage (excludes scheduled maintenance)
  • Status Page: status.timbuktoo.app (real-time status)

Monitoring & Alerting

  • Real-Time Monitoring: Datadog, AWS CloudWatch, Firebase Crashlytics
  • Uptime Monitoring: Pingdom (external monitoring, 1-minute intervals)
  • Alert Channels: PagerDuty (on-call rotation), Slack (engineering channel)
  • Response Time: < 15 minutes for P0 incidents, < 1 hour for P1 incidents

Incident Response

  • Incident Commander: On-call engineer (24/7 rotation)
  • Escalation: P0 → CTO, P1 → Engineering Lead
  • Communication: Status page updates every 30 minutes during incidents
  • Post-Mortem: Required for P0/P1 incidents (root cause analysis, remediation plan)

Disaster Recovery

  • Backups: Daily automated backups (AWS RDS, S3)
  • Backup Retention: 30 days (daily backups), 90 days (weekly backups)
  • Recovery Time Objective (RTO): 4 hours (time to restore service)
  • Recovery Point Objective (RPO): 24 hours (maximum data loss)
  • DR Testing: Annual disaster recovery tests (simulated outage, restore from backup)
